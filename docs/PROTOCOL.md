# Протокол Insta360 Luna Ultra

Заметки, взятые из `apatassini/Insta360luna` (MIT) и `RigacciOrg/insta360-wifi-api` (GPLv3),
сопоставленные с измерениями на аппарате. Полевые и командные числа используются как есть;
код приложения описывается ниже.

## Transport

TCP `192.168.42.1:6666`. Фрейминг **UCD2**, данные — **protobuf** (`insta360.messages`).

```
 0   4   'U' 'C' 'D' '2'      magic
 4   1   0x01                 версия
 5   1   0x0c                 флаги
 6   1   тип                  0x01 медиа, 0x04 команда/ответ, 0x05 поток
 7   1   seq                  8-битный счётчик
 8   4   len (LE)             длина тела
12   len тела
     4   trailer (LE)         контрольная сумма по magic..тело
```

### Контрольная сумма

Нестандартный вариант CRC-32: полином `0x04C11DB7`, инициализация `−1`, и для каждого байта
XOR с **младшим** байтом, затем **четыре** прогона по таблице старшего байта. Это не
стандартный CRC-32, и его не стоит «чинить»: камера отбрасывает фреймы с неверным trailer.

### Открытие сессии

Команды входа не существует. Разрешение даётся отправкой фрейма **типа поток** (`0x05`) с
нулевой длиной и постоянным токеном `f6 cc 4f 09` вместо trailer; он повторяется каждые
**3 с** как keep-alive. Сессия стабилизируется примерно через 1500 мс после первого фрейма.

Если соединение падает в течение 5000 мс после открытия, причина почти всегда в том, что у
камеры **одна управляющая сессия**: официальное приложение Insta360 нужно полностью закрыть.

### Команды

Тело фрейма команды начинается с 9 байт:

```
 0   2   code (LE)
 2   1   направление         0x02 запрос, 0x03 ответ
 3   2   requestId (LE)       именно он связывает запрос и ответ, а не seq
 5   4   0x00008000 (LE)      константа
 9   ..  сообщение protobuf
```

Три поведения, которые нельзя принимать на зуб:

- ответ **не** повторяет код команды: он всегда равен `200`;
- камера **не** отправляет сообщения `Error`: на несуществующий код, на мусорный payload и на
  настоящую команду без аргументов она отвечает одинаково — `200` с пустым телом;
- `TAKE_PICTURE` отвечает, когда **приняла** кадр, а не когда файл записан. Решение
  приходит в виде уведомления (8208 со статусом занято, либо 8201 с кодом ошибки).

### Коды

| код | команда |
|---|---|
| 3 | `TAKE_PICTURE` |
| 4 / 5 | `START_CAPTURE` / `STOP_CAPTURE` |
| 7 / 8 | `SET_OPTIONS` / `GET_OPTIONS` |
| 9 | `SET_PHOTOGRAPHY_OPTIONS` |
| 11 | `GET_FILE_EXTRA` |
| 12 | `DELETE_FILES` |
| 13 | `GET_FILE_LIST` |
| 15 | `GET_CURRENT_CAPTURE_STATUS` |
| 118 | `SET_ACCESS_CAMERA_FILE_STATE` — **НЕ отправлять** (см. раздел «Гимбал») |
| 16 | `SET_FILE_EXTRA` (молчаливый no-op на этом прошивке) |
| 17 / 18 | `GET` / `SET_TIMELAPSE_OPTIONS` |
| 22 / 23 | `START` / `STOP_TIMELAPSE` |
| 30 | `GET_MINI_THUMBNAIL` (не реализовано) |
| `0x00E2` | `GIMBAL_CONTROL` |

Как корректные команды не подтверждались: 6, 12 (в смысле «не использовать»), 24, 32, 33,
34, 40, 56, 57, 85, 112.

### Уведомления

| код | содержимое |
|---|---|
| 8195 | батарея (поле 2 уровень, поле 3 масштаб) |
| 8198 / 8199 | накопитель |
| 8201 | съёмка прервана: 1 карта полна, 2 занята, 4 карта медленная, 7 батарея, 9 температура |
| 8208 | статус съёмки: поле 1 статус, 2 время, 3 число кадров |
| 8220 | выдержка |
| `0x206A` | скорость гимбала |
| 8302 | PTZ (не подтверждён) |

Статусы съёмки: `4` = ведётся одиночный кадр, `15` = ведётся панорама, `0` = свободно.

### Гимбал

Камера выполняет `GIMBAL_CONTROL` (`0x00E2`) **только пока идёт прямой эфир** (live view).
Без активного эфира команда acknowledge (пустой `200`), но игнорируется. Поэтому перед
любым движением гимбала должен быть запущен **стрим**: `START_LIVE_STREAM` (код 1) на
подключении TCP. Прямой эфир OSC-MJPEG (HTTP `camera.getLivePreview`) показывает картинку,
но сам gate гимбала запускает именно TCP `START_LIVE_STREAM`.

**Не отправлять** `SET_ACCESS_CAMERA_FILE_STATE` (118, `AccessState.LIVE_VIEW=5`): оба
проверенных референса (`apatassini/Insta360luna`, `Ripwords/insta360-luna-ultra-desktop`)
запускают эфир **только** `START_LIVE_STREAM`. Команды доступа к файлам меняют состояние
камеры и на прошивке 1.0.288 уводят её из состояния, в котором active gate гимбала —
при этом TCP-соединение живо, но управление гимбалом отсутствует.

`GIMBAL_CONTROL` (`0x00E2`), поле 1 = действие, поле 2 = вложенное сообщение с осями в
зигзаге:

- `08 01 12 <len> <axes>` = `MOVE`; `12 00` (пустые оси) = **стоп**, отправляется 4 раза
  через 25 мс;
- вложенное поле 1 = `device_x` = **вертикально**, поле 2 = `device_y` = **горизонтально**,
  диапазон −100…100;
- действия без осей: 2 = вернуться в центр, 3 = переключить фронтальную камеру.

### Панорама (встроенный режим камеры)

Официальная приложение Insta360 делает 360-панораму **встроенным режимом камеры**, а не
склейкой на телефоне: камера сама ведёт гимбал по **19 позициям**, делает снимки и
**выполняет stitching внутри себя**, сохраняя **один** готовый 360-JPG (8000×4000, ~32 Мп).
Оригиналы 19 кадров не сохраняются — камера их не выдаёт, только сшитый результат. Приложение
не двигает гимбал при этом режиме: гимбал ведёт камера.

Секвенция команд (подтверждена референсом `apatassini/Insta360luna`, verified на Luna Ultra):

1. `SET_OPTIONS` + `photo_sub_mode = PHOTO_INSTA_PANO (8)` — камера переходит в панорамный режим
   (`FunctionMode = NORMAL_POWER_PANO_IMAGE = 14`). Без этого `TAKE_PICTURE` не делает панораму.
2. `SET_PHOTOGRAPHY_OPTIONS` + `PANO_ASPECT (98) = SPHERE_360 (1)` под `function_mode =
   NORMAL_POWER_PANO_IMAGE` — задаёт 360-сферу (4 = 2:1). **Это ключевая команда:** без неё
   камера остаётся в INSTA_PANO, но не запускает встроенный панорамный цикл.
3. **ОДИН** `TAKE_PICTURE` с `isInstaPanoEnabled=true` (поле 1 = mode, поле 5 = true) — и камера
   делает всю панораму внутри. Ответ `TakePictureResponse.photo.uri` — путь к готовому 360-JPG
   на камере.

После этого готовый 360-JPG скачивается с камеры по HTTP (`http://192.168.42.1<uri>`) и
сохраняется на устройство. Дожидаться `GET_CURRENT_CAPTURE_STATUS` (статус `15` = ведётся
панорама, `0` = свободно), потому что `TAKE_PICTURE` отвечает, когда камера **приняла**
запрос, а не когда записала файл.

## HTTP

- Файлы: `http://192.168.42.1<path>`, например
  `/storage_internal/DCIM/Camera01/IMG_…jpg`.
- Live-превью: `POST /osc/commands/execute` с `{"name":"camera.getLivePreview"}`,
  поток MJPEG, который читается как последовательность `FF D8 … FF D9`.
- `camera.listFiles` требует заголовок `X-XSRF-Protected: 1`.

## Wi-Fi

SSID с префиксом `Luna Ultra`, подсеть `192.168.42.`, шлюз `192.168.42.1`. У сети нет
интернета: socket нужно привязывать к `Network` Wi-Fi и держать регистрацию сети через
`NetworkRequest`, иначе Android сбросит её, как только приложение выйдет на передний план.
