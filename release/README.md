# PanoLuna

Android-приложение для Insta360 Luna Ultra: управляет камерой по Wi-Fi и снимает
24 отдельных кадра сферической панорамы для последующей сшивки на компьютере.
Камера сохраняет снимки на свою карту; приложение не выполняет сшивку.

## Возможности

- Подключение к Wi-Fi камеры выполняется вручную на телефоне (обычный адрес камеры
  `192.168.42.1`). Приложение удерживает соединение с сетью камеры и управляет ею по TCP.
- Главный экран показывает live-превью, состояние камеры и управление съёмкой: старт,
  пауза, продолжение и остановка. Отдельного экранного джойстика в текущем интерфейсе нет:
  гимбал перемещается автоматически по точкам плана.
- План по умолчанию — 4 ряда × 6 столбцов, всего 24 кадра. Панорамная последовательность
  использует обычный одиночный режим фото. Приложение не задаёт разрешение, RAW, экспозицию,
  баланс белого или зум; эти параметры выбираются на камере.
- Доступны настройки адреса/порта, таймаута, масштаба управления гимбалом, темы и языка
  интерфейса (русский, английский или системный).

## Структура

| Путь | Назначение |
|---|---|
| `android/app/` | Java-исходники, ресурсы и манифест Android-приложения |
| `android/build.sh` | Сборка APK без Gradle/установленного Android SDK |
| `android/test.sh` | JVM-проверки протокольных сериализаторов и плана панорамы |
| `android/tools/` | Вспомогательные инструменты и JVM smoke-тест |
| `docs/PROTOCOL.md` | Формат UCD2, protobuf-команды и известные ограничения протокола |
| `docs/CODE_AUDIT.md` | Результаты аудита исходников и оставшиеся вопросы |
| `templates/`, `release/templates/` | Шаблоны/артефакты для внешнего процесса сшивки; не являются экранным экспортом приложения |

## Сборка и тесты

```bash
bash android/test.sh       # компилирует и запускает чистые JVM-проверки
bash android/build.sh      # собирает APK; использует инструменты из android/tools/
```

Сборочный скрипт при необходимости получает зависимости из npm/PyPI. JVM-тесты не заменяют
проверку на физической камере: они проверяют локальную сериализацию, планирование и генерацию
части текстовых форматов, но не подтверждают реакцию прошивки на сетевые команды.

## Протокол и съёмка

Управляющее TCP-соединение использует UCD2 и protobuf. Ответ камеры с кодом 200 означает
получение ответа, но не всегда подтверждает применение команды. После `TAKE_PICTURE` приложение
отдельно ждёт завершения захвата перед следующей точкой. Подробнее о кадрировании, командах
и неопределённостях — в [`docs/PROTOCOL.md`](docs/PROTOCOL.md).

Алгоритмический аудит, включая расчёт физического шага панорамирования и проверяемые
ограничения, описан в [`docs/CODE_AUDIT.md`](docs/CODE_AUDIT.md).
